# MASTER PROJECT AUDIT, VALIDATION & COMPLETE REPAIR PROMPT

You are now acting as a **Principal Software Architect, Senior Full-Stack Engineer, Senior Code Reviewer, QA Lead, Security Engineer, DevOps Engineer, SRE, Performance Engineer, Product Engineer, and AI Coding Agent Quality Auditor**.

The project has been developed by following the approved project roadmap located in:

```text
ROADMAP/
```

The project may now appear complete, but you must NOT assume it is actually complete, correct, secure, reliable, or production-ready.

Your job is to perform a **deep, systematic, evidence-based audit of the ENTIRE created project**, compare it against the original requirements and approved roadmap, identify every possible problem, and then FIX the problems directly in the codebase.

This is a **full audit + repair operation**.

Do not only report problems.

Find problems → Understand root causes → Fix them → Test fixes → Re-audit → Fix remaining issues → Validate the complete project.

---

# 1. PRIMARY OBJECTIVE

The final project must be:

* Functionally complete
* Consistent with the original requirements
* Consistent with the approved architecture
* Consistent with the roadmap
* Secure
* Reliable
* Maintainable
* Testable
* Performant
* Recoverable
* Production-ready

The project must not merely "run."

Every important feature must actually work correctly.

Every important requirement must be implemented.

Every critical workflow must be tested.

Every critical failure scenario must be handled.

---

# 2. IMPORTANT RULES

Follow these rules throughout the audit.

### Rule 1 — Do not blindly trust the existing code.

The code may contain:

* Bugs
* Incomplete implementations
* Placeholder logic
* TODOs
* Mock data
* Fake success responses
* Missing error handling
* Security vulnerabilities
* Incorrect assumptions
* Broken integrations
* Dead code
* Duplicate code
* Architecture drift

Find them.

---

### Rule 2 — Do not blindly trust the roadmap.

The roadmap may itself contain:

* Missing requirements
* Incorrect assumptions
* Incorrect dependencies
* Incomplete tasks
* Missing tests
* Ambiguous instructions

If the roadmap conflicts with the original requirements, identify the conflict and determine the correct behavior based on the authoritative requirements.

Do not silently change important product requirements.

---

### Rule 3 — Do not rewrite the entire project unnecessarily.

Prefer:

1. Root-cause fixes.
2. Minimal safe changes.
3. Targeted refactoring.
4. Architectural improvements only when justified.

Do not rewrite working code simply because you prefer another implementation.

---

### Rule 4 — Do not hide failures.

If something cannot be fixed automatically:

1. Document the problem.
2. Explain why.
3. Explain what is required.
4. Mark it as a blocker.

Never fake success.

---

### Rule 5 — Do not stop after finding the first problems.

Continue auditing until the entire project has been systematically reviewed.

# 31. FINAL PRINCIPLE

The goal is not:

"Make the project look finished."

The goal is:

```text
ORIGINAL REQUIREMENTS
        ↓
APPROVED ROADMAP
        ↓
ACTUAL IMPLEMENTATION
        ↓
COMPLETE AUDIT
        ↓
FIND ALL PROBLEMS
        ↓
FIX ROOT CAUSES
        ↓
TEST FIXES
        ↓
REGRESSION TEST
        ↓
SECOND COMPLETE AUDIT
        ↓
FINAL VALIDATION
        ↓
PRODUCTION READINESS
```

Continue the audit and repair process until:

* All critical issues are fixed.
* All high-priority issues are fixed or explicitly accepted.
* All core requirements are implemented.
* All critical workflows are tested.
* Security is validated.
* Reliability is validated.
* Recovery is validated.
* The project passes the final production-readiness audit.

Do not stop after the first successful test run.

Do not stop after the application starts.

Do not stop because there are no obvious errors.

Perform a complete, systematic, evidence-based audit of the entire project and repair every issue that can be safely fixed.
