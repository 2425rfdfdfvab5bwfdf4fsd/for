🪟 Windows Automation Pro Features — Full Deep Analysis
🚀 1. Full Boot-to-Trade Automation Pipeline
The most powerful Windows feature: zero human intervention from cold boot to live trading.

PC powers on
  → Windows auto-logs in silently (netplwiz)
  → Task Scheduler fires autostart.bat at logon
  → Sleep prevention locks ON (two-layer)
  → MetaTrader 5 launched automatically if not running
  → Bot waits ~120s for MT5 to appear, then 20s login grace
  → python main_manual.py --auto starts (logged to logs\)
  → Telegram receives trade alerts all day
  → Bot exits → original sleep timeout restored automatically

No keyboard, no mouse, no manual steps after setup.

😴 3. Dual-Layer Sleep Prevention
Windows will kill a sleeping process. The bot blocks this at two independent levels simultaneously:

Layer 1 — OS Power Settings (autostart.bat)
powercfg /change standby-timeout-ac 0

Sets AC sleep to Never before the bot starts
Saves your original setting first via PowerShell registry read
Restores it automatically when the bot exits (exact original value, or 30-min fallback if registry read failed)
If PC is hard-rebooted mid-run, the doc tells you how to restore manually
Layer 2 — Kernel-Level Power Request (sleep_guard.py)
SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED | ES_AWAYMODE_REQUIRED)

Calls Windows kernel32.dll directly via ctypes
ES_SYSTEM_REQUIRED — CPU cannot sleep
ES_AWAYMODE_REQUIRED — blocks sleep even when screen is locked or idle
Registered with atexit — releases automatically even on crash/exception
Verify anytime with powercfg /requests — python.exe appears under SYSTEM
Silent no-op on Linux/macOS (safe to import anywhere without platform guards)
Why two layers? If the OS setting is changed externally while the bot runs (e.g. Windows Update, Group Policy), Layer 2 still holds. If the Python process fails to acquire the kernel lock (rare permissions issue), Layer 1 still protects.

💡 5. Hibernate & Fast Startup Elimination
Problem: Windows Hibernate (S4) is a full RAM-to-disk shutdown — the bot process cannot survive it, even with sleep prevention active.

Solution (one-time, documented):

powercfg /h off

Plus disable Fast Startup (which uses hibernate under the hood): Control Panel → Power Options → Choose what the power buttons do → Turn off fast startup

After this, the only idle state the PC can enter is Sleep (S3) — which is fully blocked by the dual-layer sleep prevention above.

🛑 6. Three-Method Process Termination (scripts/stop-bot.bat)
Stopping the bot safely handles every edge case — window title changes, WMIC removal on Windows 11, etc.:

Method 1 — PID File (Primary)
set /p BOT_PID=<data\bot.pid
taskkill /f /pid %BOT_PID%

The bot writes its own PID to data/bot.pid at startup. Kill is exact and instant.

Method 2 — Window Title Kill (Fallback)
taskkill /f /fi "windowtitle eq SMC Bot - AUTO-TRADE MODE"

Covers every known window title variant the bot can have (Manual, Auto, Backtester, Setup Wizard, Connection Test).

Method 3 — Script-Name Filter (Last Resort)
taskkill /F /FI "IMAGENAME eq python.exe" /FI "WINDOWTITLE eq *main_manual.py*"

Uses taskkill filters instead of deprecated WMIC — works on all Windows versions including Windows 11 builds where WMIC was removed.

Note on Task Scheduler: stop-bot.bat kills the process, but the Scheduler's "Restart on Failure" will relaunch it up to 3 times. To prevent restart, disable/remove the task via the uninstall script.

🖥️ 7. Smart double-click Guard (autostart.bat)
Problem: When you double-click a .bat file, Windows runs it via cmd /c — the window closes the instant the script exits, even on error. You can't see what went wrong.

Solution — self-relaunching guard:

if not defined _SMC_LAUNCHED (
    set _SMC_LAUNCHED=1
    cmd /k ""%~f0" %*"
    exit /b 0
)

First run: relaunches itself under cmd /k (window stays open), sets _SMC_LAUNCHED
Second run: _SMC_LAUNCHED is defined, skips the guard, executes normally
Task Scheduler is unaffected — it sets its own environment, never defines _SMC_LAUNCHED, so the guard is skipped and the task exits cleanly (enabling proper restart tracking)
This solves a subtle race condition: if Task Scheduler used cmd /k, it would orphan as a background process and allow a second bot instance to spawn on next logon.

📅 8. Cross-Version Date Stamping for Log Files
Problem: wmic (used for date formatting) was removed from some Windows 11 builds.

Solution — two-tier date resolution:

:: Try PowerShell first (all Windows versions)
for /f ... powershell -Command "Get-Date -Format 'yyyy-MM-dd'"
:: Fallback to wmic for old Windows 10
for /f ... wmic os get LocalDateTime

Log files are always named logs\autostart_2026-07-25.log regardless of Windows version. A new file is created each day — old logs are never overwritten.

🔍 9. MT5 Process Detection & Readiness Polling
The bot doesn't blindly launch MT5 and immediately try to connect:

:: Step 1: Check if MT5 is already running
tasklist /fi "imagename eq terminal64.exe" | find /i "terminal64.exe"
:: Step 2: If not running, launch it
start "" "%MT5_PATH%"
:: Step 3: Poll until it appears (up to 120 seconds)
:wait_loop
  timeout /t 5 /nobreak
  tasklist | find "terminal64.exe" → if found, goto :mt5_ready
  set /a elapsed+=5
  if elapsed >= MT5_WAIT_TIMEOUT_SECONDS → error and exit
:: Step 4: Login grace period (20s for price sync)
timeout /t 20 /nobreak

MT5 path read from .env (MT5_PATH) — fallback to standard install location
Configurable timeout (MT5_WAIT_TIMEOUT_SECONDS=120)
Configurable login grace (MT5_LOGIN_GRACE_SECONDS=20)
Manual mode scripts (run-manual.bat, run-auto.bat) also check MT5 is running before starting and pause with a Y/N prompt if not — prevents silent failures
